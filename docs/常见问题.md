# 常见问题与排查

## 先看日志

90% 的问题看一眼日志就能定位：

```
<安装目录>\logs\boot-notify.log
```

日志按时间记录了：是否检测到开机、开机时间、网络状态、每次发送结果、钉钉返回的 `errcode / errmsg`。

也可以开控制台模式手动复现：

```powershell
cd D:\DingBootNotify
powershell -ExecutionPolicy Bypass -File .\DingBootNotify.ps1 -DryRun    # 只打印，不发
powershell -ExecutionPolicy Bypass -File .\DingBootNotify.ps1            # 真发
```

---

## 钉钉返回 errcode 310000

`310000` 是钉钉自定义机器人的「安全校验 / 内容校验失败」，常见三种原因：

1. **中文乱码**
   自己改脚本，把中文直接写进 `.ps1` 并保存成「UTF-8 无 BOM」，Windows PowerShell 5.1 会按 GBK 解析，中文变乱码，钉钉拒收。
   ✅ 本项目已规避：中文只在 `config.json`，脚本以 UTF-8 显式读取。请不要把中文改回 `.ps1` 里。
   如果确实要改脚本，保存为 **UTF-8 带 BOM**。

2. **加签错误**
   机器人开了「加签」，但 `config.json` 的 `secret` 没填 / 填错 / 填成了 Webhook。
   ✅ `secret` 是 `SEC` 开头那一串；没开加签就留空字符串。

3. **关键词不匹配**
   机器人安全设置选了「自定义关键词」，但消息里没有该关键词。
   ✅ 把关键词设为「开机提醒」（默认模板里就有），或改用「加签」。

## 手动跑有消息，开机没消息

按顺序排查：

### 1. 任务是否存在、是否启用

```powershell
Get-ScheduledTask -TaskName DingBootNotify | Format-List TaskName, State
```

`State` 应为 `Ready`（或正在运行）。没有任务说明没建成功，重新安装。

### 2. 任务是否真的被触发

任务计划程序 → 找到任务 → 右键「历史记录」（若未启用，先在右侧「启用所有任务历史记录」）。

看有没有「任务已启动」的记录：

- 没有记录 → 触发器不是「开机时」，或系统没重启只是注销
- 有记录但结果代码非 0 → 看下一节

### 3. 任务执行结果代码

```powershell
Get-ScheduledTaskInfo -TaskName DingBootNotify | Format-List LastRunTime, LastTaskResult
```

`LastTaskResult = 0` 表示脚本正常退出；`0x1` 等非 0 通常是找不到 `RunNotify.vbs` 或配置报错。

常见原因：

- 安装目录被移动 / 删除，任务里的路径还是旧的 → 改任务「操作」里的参数
- 安装目录放在 **OneDrive / 坚果云等同步盘**，文件是「按需下载」的云占位，SYSTEM 账户读不到 → 换到本地磁盘（如 `D:\DingBootNotify`）
- 杀毒软件拦截了 `wscript.exe` 或 `powershell.exe` → 给安装目录和这两个程序加白名单

### 4. VBS 路径

打开任务属性 →「操作」→ 确认：

- 程序：`wscript.exe`
- 参数：`"D:\DingBootNotify\RunNotify.vbs"`（引号要在，路径要对）

手动双击 `RunNotify.vbs` 能发消息，说明问题只在任务配置。

### 5. 运行账户

- 选「不管用户是否登录都要运行」：需要勾「不存储密码」，否则保存时会一直要密码
- 更稳的做法：把运行账户改成 `SYSTEM`

## 开机后收到的是「延迟推送」，时间是几分钟前

这是正常设计：开机瞬间网卡还没就绪，脚本先把**真实开机时间**记到 `state\pending-boot.txt`，联网后再补发，所以「记录开机时间」比「发送时间」早。

默认最多等 10 分钟，可用 `retryMaxSeconds` 调整（单位秒，例如 900 = 15 分钟）。

如果超过等待时间仍没网：

- 记录文件会保留；
- 下次开机会拿它补发一条「延迟推送」（时间是上一次开机时间）；
- 想丢弃这条旧记录，直接删除 `state\pending-boot.txt`。

## 笔记本合盖 / 电池模式不触发

安装脚本已默认设置「允许电池运行」。手动建任务的，去任务属性「条件」选项卡，取消「只有计算机使用交流电源时才启动此任务」。

注意：Windows 快速启动（Fast Startup）下，「关机再开机」有时不算真正的启动事件。要验证开机触发，请用「重启」，或按住 Shift 点关机。

---

## 消息里的时间不对

- 脚本取的是 WMI `Win32_OperatingSystem.LastBootUpTime`（系统真实开机时间），不是脚本运行时间
- 时间格式为 `yyyy-MM-dd HH:mm:ss`，跟随系统时区
- 系统时间本身不准 → 校准 Windows 时间

---

## 多台电脑共用一个机器人

可以。每台机器安装一份，`deviceName` 填不同名字（如「工作站-01」「家里的台式机」），消息里用 `{device}` 区分即可。同一个 Webhook 支持多设备调用（注意钉钉机器人有频率限制，每分钟 20 条，开机通知远低于此）。

---

## 修改配置后不生效

确认改的是**安装目录**里的 `config.json`（默认 `D:\DingBootNotify`），不是 Git 仓库里的模板。改完执行：

```powershell
Start-ScheduledTask -TaskName DingBootNotify
```

看日志确认新模板生效。

---

## 卸载后开机还会收到消息

任务没删干净。管理员 PowerShell：

```powershell
Get-ScheduledTask -TaskName DingBootNotify
Unregister-ScheduledTask -TaskName DingBootNotify -Confirm:$false
```

如果当初手动建的任务名是别的（例如「电脑开机钉钉提醒」），把任务名换掉即可。旧版脚本（D:\Kaijituishong）也要一并删任务和目录。

## 仍然搞不定

提 Issue 时请附上：

1. `logs\boot-notify.log` 最后 30 行（**先删掉 Webhook / secret**）
2. `Get-ScheduledTaskInfo` 的输出
3. 系统版本（`winver`）和是台式机还是笔记本
